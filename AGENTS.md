# Agent notes

- API design: adding or changing any public name, option, return value, default or error (JS `api.*`, `origine:@std/*`, natives) starts from [docs/api-guidelines.md](docs/api-guidelines.md).
- `std.Io` is banned from the binary: no `std.Io.Threaded`, `std.Io.Dir`, `std.Io.File`, `std.Options.debug_io` and nothing that takes an `io: std.Io` (it links every `Io` operation, sockets and a thread pool for a few file calls). Use [src/fs_light](src/fs_light/README.md) for files, directories and the terminal (through `src/managed/sys.zig`, which has the `std.Io.Dir`/`File` shape of Zig 0.17 minus the `io` parameter; `src/managed/stderr.zig` for diagnostics) and the `oio_*` runtime in [src/io](src/io) for asynchronous work. Exempt: `std.Io.Reader`, `std.Io.Writer` and the plain data types `std.Io.Limit` and `std.Io.Timestamp`. Do not call `std.debug.print` or `std.log` (use `m.stderr.print`); `std_options_debug_io` is `std.Io.failing` in both roots so a stray use fails instead of linking `Threaded`. Tests may use `std.testing.io` and `std.Io` for their own fixtures, never in code that ships.
- Rust errors: no stringly-typed errors (`Err("...".into())`, `NativeError::error("...")`, `String` payloads that code later matches on). Model failures as enums, one variant per cause, and reuse the enums of the crates underneath (hickory-proto's `ProtoError`/`ResponseCode`, rustls' `Error` and `CertificateError`, `io::ErrorKind`) as variants or `#[source]`s instead of flattening them to text. Keep enums small: `Box` a large payload so the `Result` stays cheap. Human-readable text comes from `fmt::Display` (and `Debug`) on the enum, written once, never built at the failure site; implement `std::error::Error` with `source()`. Map to guest errno codes with a `match` on the enum (see `tls_error` in `rust/crates/origine_api/src/tls.rs`); the `subject` detail may be a short `Display` of the variant's payload. A free-form string is allowed only for text that comes from outside (a PEM parser message, a peer's alert name).
