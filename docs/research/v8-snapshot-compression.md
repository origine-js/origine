# V8 startup snapshot compression

Investigated 2026-11-05 against V8 15.8.30, revision `a98309795399032afd2f191adaa94ed6e9918437`, pinned in [MODULE.bazel](../../MODULE.bazel#L68-L72).

## What the flag does

`v8_enable_snapshot_compression` is a GN build argument. The pinned upstream default is on for Android, ChromeOS, and Fuchsia. Enabling it defines `V8_SNAPSHOT_COMPRESSION`, compiles V8's snapshot compressor, and requires `v8_use_zlib=true`. [GN default](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/BUILD.gn#L379-L382), [zlib requirement](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/BUILD.gn#L959-L960), [define](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/BUILD.gn#L1542-L1544), [source and dependencies](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/BUILD.gn#L6935-L6937), [zlib targets](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/BUILD.gn#L7494-L7499).

V8 keeps the startup blob's outer header and offsets. It independently compresses the isolate startup, read-only heap, shared heap, and each context section. Each compressed section starts with a 32-bit uncompressed length followed by raw DEFLATE produced by zlib at its default compression level. The same serialization path serves `mksnapshot` and embedder-created `SnapshotCreator` blobs. Embedded builtin machine code is written separately, and JS code-cache payloads use their own serializer. [Blob assembly](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/snapshot.cc#L530-L596), [codec](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/snapshot-compression.cc#L22-L58), [mksnapshot](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/mksnapshot.cc#L304-L307), [SnapshotCreator](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/snapshot.cc#L1185-L1194), [code-cache serialization](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/code-serializer.cc#L767-L787).

Each snapshot-backed isolate inflates the three isolate sections into temporary buffers before deserializing them. Each context restored from a snapshot inflates its own section on demand. The storage saving therefore comes with CPU and transient allocation costs at isolate and context creation. The reader selects the format at compile time, so a V8 version match alone cannot establish compatibility across the two settings. Generate and consume the blobs with matching builds. [Restore paths](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/snapshot.cc#L137-L220), [decompression buffers](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/snapshot-compression.cc#L67-L97).

## How this fits Origine

- **Zig/GN.** Origine's GN defaults set `v8_enable_snapshot_compression=false` and already enable zlib. To try the V8 flag, set it to true in the generated GN arguments, rebuild V8, and regenerate the Origine snapshot with the matching library. The build keys GN output directories by the rendered arguments. [GN defaults](../../lib/v8_zig/build-tools/gn/.gn#L59-L61), [argument rendering and output path](../../lib/v8_zig/build/v8.build.zig#L289-L298), [snapshot generation](../../build.zig#L167-L184).
- **Bazel.** The pinned upstream overlay lists the flag as a comment. Enabling it there requires a build setting that supplies the define, compressor source, and Chromium zlib helper and library dependencies to the V8 code shared by `mksnapshot` and the runtime. Origine's own snapshot generator already builds in the runtime's target configuration. [Pinned Bazel overlay](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/BUILD.bazel#L61-L69), [GN dependency wiring](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/BUILD.gn#L7494-L7499), [Origine generator](../../src/BUILD.bazel#L172-L187).
- **Origine's LZ4 options.** Bazel's `-C engine-snapshot` wraps Origine's entire frozen-intrinsics blob and expands it once per process. The GN flag changes the V8 format inside that wrapper and affects the V8 seed, Origine's frozen-intrinsics snapshot, and cached init snapshots. Compare with the outer wrapper disabled to isolate the GN flag's effect. Rebuild cached init snapshots for the variant as well. Origine normally segregates these caches using the executable identity, size, and mtime. [LZ4 settings](../../build/bazel/features.bzl#L31-L45), [process startup](../../src/main.zig#L53-L60), [unpack](../../src/main.zig#L333-L344), [engine snapshot creator](../../src/managed/snapshot.zig#L25-L58), [init snapshot creator](../../src/managed/init_snapshot.zig#L304-L345), [cache key](../../src/api/init_cache.zig#L118-L144).

## Size illustration

An offline reproduction of V8's section framing on the cached macOS arm64 release seed (`mac-arm64-release-b494e6a5f5aa125f/gen/snapshot.cc`) reduced it from **344,952 to 74,900 bytes (78.3%)**. The 96-byte outer header stayed the same size. Read-only went from 282,864 to 54,134 bytes, startup from 10,288 to 2,132, shared heap from 5,544 to 3,982, and context 0 from 46,160 to 14,556. The check extracted the generated byte array, split it using the header offsets, ran host zlib 1.2.12 with raw DEFLATE at the default level, added four bytes per section, and verified the decoded sections round-tripped. This estimates the seed size only. A compression-enabled build and measurements of executable size, startup time, and RSS remain untested. [V8 section framing](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/snapshot.cc#L570-L629), [compression settings](https://github.com/v8/v8/blob/a98309795399032afd2f191adaa94ed6e9918437/src/snapshot/snapshot-compression.cc#L29-L56).
